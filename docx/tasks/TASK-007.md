## 场景与学习目标

设备监控通常需要连续读取；用户停止采集时，正在等待的读取也应停止。读取设备 ID、每次等待时间来自 JSON 配置，正常流程完成三次读取，取消流程在一次读取等待期间发出停止请求并结束。

只使用现有 .NET API、模拟设备，不接真实设备或新增框架。复用 [DeviceConfig 类型](../../Base/Exercises/TASK-006-json-config/Task006Exercise.cs) 与 [Reading 类型](../../Base/Exercises/TASK-001-device-model/Task001Exercise.cs)；TASK-006 的私有保存/加载方法不能直接跨类调用，开始时检查安全复用方案，保留已有作品。

## 用户实践与产出

1. 在本任务自己的配置文件中准备设备 ID 与正数 ReadDelayMs，加载后输出字段；沿用已学的缺失/损坏提示，加载不覆盖改动。
2. 正常场景顺序执行三次异步模拟读取，逐次 await，每次输出序号、设备 ID、数值与单位；每次等待都由配置决定。
3. 取消场景由调用方创建并管理 CancellationTokenSource，将同一源的 Token 经采集循环、读取方法传入支持取消的等待 API；在等待完成前请求取消。
4. 专门捕获 OperationCanceledException，输出采集已取消；被取消的这次读取及后续轮次不输出成功读数，流程安全结束。
5. 结合自己的运行日志或代码注释标出条件、取消源、令牌与响应等待的对应关系，并管理取消源生命周期。以实际实践检验，不设动手前问答或单独口试。
