### 先让一个具体字节出现在屏幕上

本题先观察设备样例AA 01 03 00 64 5F中的一个字节64，不急着猜它表示什么设备读数。

```csharp

```

byte是C#关键字，表示能保存0～255整数的一个字节，sample是我们自行命名的变量；这一行让sample保存数值100。
0x是C#中十六进制数值的开头标记，64两位按十六进制计算为6×16＋4，也就是十进制100；十六进制的一位从0数到9之后继续用A、B、C、D、E、F表示10～15。[Microsoft Learn：整数类型与数值写法](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/integral-numeric-types)
Console是.NET提供的控制台类，WriteLine是它的输出方法，Console.WriteLine(sample)读取sample的数值并默认显示成十进制100。
因此写入时用了0x，不代表以后所有输出都会自动使用十六进制。

### 再单独改变显示方式

完成首步后，再在TODO 1b处补这一行：

```csharp
Console.WriteLine(sample.ToString("X2"));
```

ToString是.NET提供的数值转文字方法，这里读取同一个sample并产生文字64，随后WriteLine把这段文字输出到屏幕。
"X2"是.NET规定的格式文字，X要求大写十六进制，2要求至少两位，数值1会显示01，数值0会显示00；这里的2不会把更大的数截断成两位。[Microsoft Learn：十六进制显示格式](https://learn.microsoft.com/en-us/dotnet/standard/base-types/standard-numeric-format-strings#hexadecimal-format-specifier-x)
sample里保存的数仍是100，100和64只是同一个数的两种显示方式，ToString没有修改sample。
本段代码中的"64"是两位显示文字，而0x64是一个字节的数值，后续做通信时要分清这两者。

## Q4：TASK-042 怎样判断收齐一帧，并把它从缓冲中取出来？

- 状态：已掌握。

### 先有明确规则，才知道该等待还是取出

本题新约定一帧固定6字节、开头为AA，后5字节原样保留，没有校验或业务字段解释；输入只包含满足这些规则的合法帧及其分段。
缓冲只有AA 01时Count为2，应留下来等待；再收到03 00 64后Count为5，仍等待；最后收到5F后Count为6，才够取一帧。
6来自本题明确的教学规则，不是因为一次输入刚好有6个字节，也不代表所有设备都固定发送6字节。

### 先把这一帧另存出来，再移除已处理部分

```csharp
byte[] frame = new byte[6];
frame[0] = _receivedBytes[0];
```

new byte[6]是C#新建6位置字节数组的写法，frame是自行命名的局部变量，这6个位置刚创建时都是0。
第二行把缓冲第一个字节复制到frame的第一个位置，缓冲内容仍在原处；完整六字节的复制由学员用循环完成。
教练准备的PrintFrame(frame)只负责打印这份数组和增加显示计数，不替你复制字节，也不替你移除缓冲。

```csharp
_receivedBytes.RemoveRange(0, 6);
```

RemoveRange由.NET列表提供，0表示从下标0开始，6表示移除6项；例如8字节缓冲中包含帧A加上AA 02，复制帧A并移除前6项后，缓冲应只剩AA 02。
这里不使用Clear清掉整个列表，因为后面的AA 02属于下一帧，仍需留给后续到达的数据。

### 一次有两帧时，每取完一帧还要再看剩余数量

12字节里有帧A和帧B，取完第一帧还剩6个字节，应继续取第二帧；8字节里只有一个完整帧加两个字节，取完一帧剩2就应停止。
所以需要C#的while重复检查当前Count是否仍至少为6，而不是只判断一次就结束；每轮移除6项后再检查，数量足够才继续。
[任务卡](../tasks/TASK-042.md)先用remaining=12的最小例子解释while的两次执行与结束，学员再把这个关系用到ProcessBuffer的缓冲提取上。
如果循环一直输出却不移除已处理部分，Count不会减少，就无法通过剩余数量结束本次处理，不能把它当成成功取出多个帧。

### 首步在真实方法里只观察一次判断

教练新建的ReceiveChunk先把本段有效字节追加到共享列表，再调用ProcessBuffer，随后由PrintBufferState输出剩余数量、内容和本组已输出帧数。
在ProcessBuffer的TODO 1位置按任务卡添加if/else：Count小于6时打印继续等待，否则打印已经够一帧；第一段后应看到继续等待和缓冲数量2。
if检查括号里的比较结果后只选择一组语句执行，while则在每一轮之前重新检查；本题先观察if结果，再继续完成重复取帧。
StartScenario只在场景组之间清空和重置显示计数，每组内部持续保留缓冲；这项场景准备由教练提供，不算学员新的自主实现。
开启时教练实际运行的是ProcessBuffer未实现的骨架、帧数均为0；本次学员已经写完单帧复制/移除与打印，实际审查结果见下方记录，不能继续把当前实现说成空骨架。

### 首次审查的历史：为什么12个字节只先输出一帧

首次提交的方法先取出第一帧，再执行while (_receivedBytes.Count > 6)，所以一次收到A+B共12字节时，取完A剩6，而6 > 6为false，第二帧B留在列表里。
后续数量0调用虽然没有追加数据，仍会再次进入ProcessBuffer，从方法开头把B取出，所以最终帧内容没丢，但处理时机晚了。
本题恰好6个字节已经够一整帧，因此重复处理应包含这个相等边界，首个修改是将循环条件改为Count >= 6，再实际核对12字节输入当场输出两帧、缓冲0。
后续数量0应保持原已输出帧数，不靠它补处理此前已经完整的B；现有输出没有重复已处理帧，不能把这次问题解释成重复帧。
当前循环体里调用ProcessBuffer()会再次进入同一个方法，这种方法调用自己的写法叫递归；可以把复制/移除/打印组织在while体中直接重复，这是结构建议，当前先修正相等边界，不增加验收范围。

### 99 88与AA 01为什么不能一概等待

本题仍约定合法帧以AA开头、固定6字节，没有校验和业务字段解释，新增的人工无效字节只在帧前或帧间，且取值不是AA。
列表只有99 88时，没有合法开头，应逐个移除这两个字节；列表只有AA 01时，开头已经合法，只是还没收齐，应原样留下来等后续4个字节。
所以不能像上一题只在Count至少为6时处理，当前只有1或2个字节也可能需要清掉无效开头。

```csharp
    return;
}
Console.WriteLine("当前首字节：" + _receivedBytes[0].ToString("X2"));
```

==是C#相等比较，Count为0时没有下标0可读，第一组语句会显示缓冲为空并结束这次ProcessBuffer调用；ReceiveChunk之后的缓冲观察仍会执行。
列表非空时，_receivedBytes[0]读取实际第一个字节，ToString("X2")沿用已学过的大写两位十六进制显示。
首步完成后的预期是场景一显示当前首字节99，场景七显示缓冲为空，此时还不会删除无效字节或输出完整帧，不算DoD通过。

### 删除一项后，下标0指向了另一个字节

2026-10-19讲解修正：学员明确反馈TODO 2a“每轮只判断当前下标0”不通顺，问题在教练表达；改用下面的具体列表说明，不记学员错题或撤销已有能力。
_receivedBytes[0]就是“现在列表最前面的那个字节”，删掉它后，后面的字节会往前补。

| 现在列表里有什么 | _receivedBytes[0]读到什么 | 本题接下来做什么 |
| :--- | :--- | :--- |
| 99 88 AA 01 | 99。 | 不是AA，删掉99。 |
| 88 AA 01 | 88。 | 不是AA，删掉88。 |
| AA 01 | AA。 | 开头正确，但只有2个字节，留下来等待。 |

下标一直写0，但读到的字节依次是99、88、AA，因为每次删除后列表的内容都变了。
如果列表原来只有99 88，删掉两个字节后就空了，已经没有“第一个字节”，这时再读_receivedBytes[0]会报错，所以每次读之前先确认Count > 0。

```csharp
_receivedBytes.RemoveAt(0);
```

RemoveAt由.NET列表提供，这行只删除当前第一项；99 88 AA 01先删99后，88变成新的下标0，再删88后，AA变成新的下标0。
因此每次删除后应重新检查，不是把下标一直加大来跳过被删除的位置，也不该清空后面的AA 01。
当前第一个字节与0xAA不同，可以用_receivedBytes[0] != 0xAA判断，!=是C#不等于比较，读取前仍要保证列表非空。

### 每轮处理后怎样继续或等待

while条件围绕列表非空展开，才能处理不足6的99 88；每轮检查第一个字节，丢弃一项或消费一帧后再回到非空条件。
continue是C#控制语句，用在这类while里时，跳过本轮后续语句并重新判断while条件，例如删除99后重新检查列表里还有没有88。
break是C#控制语句，用在当前while里时结束这个循环，例如遇到AA 01只有2个字节，就保留列表并等待下一次输入；它本身不删除字节。
return结束当前方法调用并回到调用者，也可以表达本次先等后续数据；不要求为了使用新语法而强制采用某一种写法，结果要符合任务规则。

### 合法开头与数量都确认后，复用已验证的取帧辅助

ExtractOneFrame是教练新命名的普通方法，内部复用TASK-042已验证的六字节复制、RemoveRange和PrintFrame，不是.NET或串口API。
调用它之前需要由ProcessBuffer确认当前首字节为AA且Count至少为6，调用后已取出的6字节被移除，再检查剩余缓冲。
帧C是AA 03 AA 00 66 61，第三个字节AA是帧内部普通数据，应该随这6个字节一起复制，不能把内部AA当成新开头重新切分。
本题没有校验来识别假的AA开头，只验证约定的非AA前导/帧间字节跳过，不扩大为真实设备坏帧恢复已经完成。
